**DETAILS**
Advisor Engine Architecture and Schemas: Kevan Mordan explained the structure of the advisor engine, noting that it uses schemas, which are essentially markdown files with front matter, where each file represents a single object, functioning similarly to a database. The engine records interactions, signals, and decisions, and uses four skill types: delivery, delivery portfolio, growth, and growth portfolio, with the latter two focusing mainly on leads and accounts (00:00:00). The system can assess delivery by looking for signals without corresponding decisions, and track metrics like the time from signal to decision, as well as tracking user interactions (00:01:40).
Advisor Engine Setup and Configuration: The lightweight wrapper for the advisor engine acts as a template and uses a sub-module for skills, which users configure via `configure advisor` (00:01:40). Configuring the advisor allows users to select skills and set the local context for their claw reference (00:02:47) (00:07:57). The setup process uses a `setup.sh` script, which requires integration with the 1Password CLI to retrieve keys like the Anthropic API key and GitLab SSH key for initialization (00:05:10).
Project Creation and Access Management: Kevan Mordan demonstrated creating a new project from the advisor template within GitLab. Abel Hernandez noted they did not have access to the repository, which Kevan Mordan addressed by granting them access later in the meeting (00:03:54).
Using the Bootstrap Project Context Skill: The `bootstrap the project context` skill processes upfront information, such as a draft Statement of Work (SOW) PDF, to establish a baseline for a project (00:13:20). This skill extracts information like milestones, identifies contractual obligations, and highlights keywords and key people from the source document (00:17:25). Kevan Mordan mentioned that users can upload various sources, including Slack JSON dumps, screenshots, and meeting transcripts, to enrich the project context (00:15:36) (00:20:46).
Generating Project Artifacts and Dictionary: The bootstrap process extracts milestones and identifies gaps in the contract, and it also identifies keyword terms, systems, and people, which are cataloged as research candidates (00:17:25). The advisor engine builds a project dictionary that organizes terms into categories like systems and platforms and domain terms (00:24:33). The system also drafts a project roadmap and records all interactions, signals, and decisions based on the processed context (00:23:24) (00:25:49).
Feedback and Collaborative Limitations: Kevan Mordan acknowledged that the current setup, which uses a Git repository as the database, is a temporary workaround that faces immediate challenges with write contentions, as multiple people creating new files simultaneously could lead to merge conflicts (00:22:08). The process outputs next steps, such as reviewing the generated sections and telling the system which to save or approve, which is part of the document lifecycle from a draft created by the AI (00:25:49).
Value Proposition and Future Plans: Coby Almond found the advisor engine "cool" and expressed interest in integrating it with Threadline, which they developed. Kevan Mordan confirmed that the long-term plan is to combine the system and potentially integrate it into an application (00:26:50). The current use of the GitLab repository makes the tool accessible and usable for any project that is Kuai approved. Kevan Mordan noted the tool is effective because it quickly queries the markdown files, acting as a local retrieval-augmented generation (RAG) system, and assists in context preparation by advising on agendas and drafting recommended questions (00:27:49).
