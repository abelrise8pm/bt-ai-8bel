I also want to be able to easily tie that version of the container back to the specific commit that created that container so I have traceability of source for my secure software supply chain.

To ensure our software supply chain is secure and verifiable, we can definitively tie any running container back to its exact source code by embedding the Git commit SHA directly into the image as a standard org.opencontainers.image.revision metadata label during our CI/CD build. This method is robust because the label becomes a permanent part of the image's immutable digest, which acts as a unique fingerprint of its content. This process works perfectly for multi-platform images because the parent manifest list simply points to platform-specific images, each of which contains the correct label and has its own unique digest. By digitally signing the manifest list's digest, we create a tamper-evident seal; any unauthorized change to the manifest or the underlying images would alter the digest, causing the signature verification to fail and allowing our systems to automatically reject the untrusted artifact.
